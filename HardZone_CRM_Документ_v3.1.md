## 2. Технический стек

### Бэкенд
- Runtime: Node.js v24, Express
- База данных: PostgreSQL 16, драйвер pg
- Процесс-менеджер: PM2
- Авторизация: Bearer токен (AUTH_TOKEN в .env)
- Парсинг Excel: библиотека xlsx + multer
- HTTP-клиент: axios (интеграция aQsi)
- Сервер: Ubuntu VPS, /srv/app, пользователь app
- Прокси: nginx 80 → Node.js 3000

### Фронтенд
- Framework: Next.js 16 (App Router)
- Стили: Tailwind CSS, тёмная тема (#0D1117)
- Язык: TypeScript
- Процесс: PM2 → порт 3001
- nginx: / → фронт (3001), /api/ → бэкенд (3000)

### Архитектура фронтенда
- lib/api/ — чистые функции запросов: products.ts, receipts.ts, writeoffs.ts, categories.ts, product-types.ts, imports.ts, inventories.ts, orders.ts
- hooks/ — React-хуки: useProducts, useReceipt, useWriteoff, useCategories, useProductTypes, useImport, useEditProduct, useArchiveProduct, useProductSearch, useInventory
- components/warehouse/ — компоненты склада
- components/sales/ — компоненты кассы

## 6. Модуль 2 — Продажи

### 6.1 Концепция

CRM является **предкассой**. Администратор формирует заказ в CRM, отправляет на терминал aQsi, кассир проводит оплату, aQsi пробивает фискальный чек, CRM получает подтверждение и списывает склад.

**Абонементы** — продаются через кассу, но без привязки к клиенту (модуль Клиенты ещё не реализован). Когда появится модуль Клиенты — абонементы привяжутся к клиентской базе.

### 6.2 Статусы заказа

| Статус | Описание | Склад |
|--------|----------|-------|
| open | Заказ открыт, собирается или отправлен на кассу | Не изменяется |
| confirmed | Оплачен на кассе aQsi | Списывается |
| cancelled | Отменён | Не изменяется |
| refunded | Возврат оформлен через aQsi | Не изменяется |

### 6.3 Позиции в заказе

Три типа (`kind`):
- `product` — товар со склада, списывается при подтверждении
- `service` — услуга, склад не трогается
- `subscription` — абонемент, склад не трогается

В одном чеке можно смешивать все три типа.

### 6.4 Процесс продажи

1. Администратор открывает `/sales` → касса
2. Ищет позиции по названию, SKU или сканером штрихкода
3. Добавляет позиции в чек
4. Нажимает "Отправить на кассу" → заказ уходит в aQsi как отложенный
5. Кассир на терминале CS10F выбирает заказ в "Отложенных заказах", клиент платит
6. aQsi пробивает фискальный чек → CRM получает подтверждение → склад списывается автоматически
7. Если вебхук не пришёл — администратор нажимает "Проверить оплату" в истории продаж
8. Если администратор забыл — CRM делает одну автоматическую синхронизацию статуса примерно через 30 минут после отправки чека на кассу

### 6.5 Возврат

- Только финансовый — деньги возвращаются клиенту через кассу aQsi
- Склад при возврате **не изменяется**
- Сейчас реализован возврат только **всего чека целиком**
- Возврат отдельных позиций — в плане
- Для возврата используются фискальные реквизиты оригинального чека (ФД, ФН, ФП, РН ККТ)

### 6.7 Скидки

- **На чек:** администратор вводит % или фиксированную сумму через `PATCH /api/orders/:id`
- **На позицию:** при добавлении или редактировании позиции через `PATCH /api/orders/:id/items/:itemId`
- Оба варианта передаются в aQsi (`discountMoney` / `discountPercent`)
- Итог в чеке показывает зачёркнутую сумму без скидки и финальный total
- Пример: 2 × Бинт 60₽ = 120₽, скидка на позицию 10₽, скидка на чек 5% → итог 104.50₽

| Параметр | Значение |
|----------|----------|
| API ключ | в .env: AQSI_API_KEY |
| Shop ID | 263355 |
| Warehouse ID | ed3ea8c1-135c-431d-973b-d94092d5d478 |
| Устройство | CS10F, серийный номер 1002063619060879 |
| Система налогообложения | УСН доход (taxationSystem: 1) |

## 9. Интерфейс

### Навигация

| Модуль | URL | Статус | Вкладки |
|--------|-----|--------|---------|
| Склад | /warehouse | В работе | Товары, История, Инвентаризация |
| Продажи | /sales | В работе | Касса, История |
| Клиенты | /clients | Заглушка | — |
| Расписание | /schedule | Заглушка | — |
| Аналитика | /analytics | Заглушка | — |

### Касса (/sales → вкладка Касса)

- Левая колонка (60%) — каталог: поиск с дебаунсом 350мс, сканер штрихкодов, карточки товаров
- Правая колонка (40%) — чек: позиции, кнопки +/−, итог, кнопка "Отправить на кассу"
- Каталог загружает только `forSale=true` — товары с остатком и услуги с ценой
- Услуги и абонементы показываются без поля остатка

### История продаж (/sales → вкладка История)

- Таблица заказов с фильтром по статусу
- Статусы: Ожидает (жёлтый) / Оплачен (зелёный) / Отменён (красный) / Возврат (оранжевый)
- Клик по строке — раскрывает позиции заказа
- Кнопки: Проверить оплату / Отменить / Возврат (в зависимости от статуса)
- Автообновление каждые 10 секунд

### История склада (/warehouse → вкладка История)

Единая лента движения товаров:
- Приёмка (зелёный, +N) — из /api/receipts
- Списание (красный, −N) — из /api/writeoffs
- Продажа (синий, −N) — из /api/orders (только confirmed)
