# Мероприятия соревнований

Первый этап: отдельные мероприятия, регистрация и подтверждённые команды по категориям. Заходы, комплексы, результаты и рейтинг пока не реализованы.

## Работа в CRM

- `/competitions`: список мероприятий, создание, переход внутрь.
- Внутри: все заявки; отдельная вкладка каждой категории только с активными оплаченными командами.
- Настройки: название, дата, место, взнос, категории, условия участия, открытие/закрытие регистрации.
- Текущий поддерживаемый формат — команда М + Ж. Индивидуальные форматы не реализованы.
- Создание по умолчанию оставляет приём закрытым. Категорию с любыми историческими заявками удалить нельзя.
- Ссылка действующего мероприятия сохраняется: `/competition`. Новые события: `/competition?event=<event_key>`.

## Данные и совместимость

Миграция `067_competition_events.sql` добавляет таблицу событий и связывает существующие заявки через внешний ключ. Записи заявок, платежей и писем не переносятся и не пересоздаются.

Настройки старого мероприятия берутся из существующего окружения, поверх применяются сохранённые настройки CRM. Категории старого события фиксированы, поскольку уже опубликованы подробные условия. Новые события содержат собственные названия категорий и условия; старую афишу и старые чаты им не подставляем.

Все новые события используют текущий терминал организатора, платную регистрацию и существующий таймер 60 минут. Стоимость сохраняется в заявке: изменение взноса влияет только на последующие заявки. Закрытие приёма не блокирует оплату уже созданной заявки.

Уникальность участников проверяется внутри события. Те же атлеты могут регистрироваться на другое событие. Повторная идентичная заявка внутри события продолжает исходную оплату.

Личные ссылки продолжают использовать уникальный `public_token`. Публичное резюме оплаты содержит название, дату, категорию и путь именно этого события. Рассылка и контроль оплаты обрабатывают все события; исторические заявки без `payment_deadline` исключены из автоматизации.

Доступ к управлению — существующее серверное право `competitions`. Ручного подтверждения оплаты нет. Удаления мероприятия/заявок интерфейс не предоставляет.

## Проверки

`scripts/test-competition-automation-remote.ps1` запускает изолированную временную БД: сохранение старых записей, изоляция событий, повторные заявки, чужие категории, защита используемых категорий, стоимость старой заявки после изменения взноса, закрытие приёма, письмо/оплата нужного события, автоматизация и подтверждённые количества. Т-Банк и SMTP в тестах подменены; реальные платежи и письма не создаются.

16 сентября 2026: 29 тестов прошли; TypeScript, lint затронутых файлов и production build прошли. Backup `hardzone_20260916_055156.dump` восстановлен во временную БД. После миграции контрольная сумма всех 9 существующих заявок совпала с исходной (5 оплаченных). Старое резюме оплаты доступно, закрытый API без сессии возвращает 401, неизвестное мероприятие — 404.

В авторизованной production CRM проверены создание закрытого события, сохранённые категории, ссылка регистрации, пустое состояние, существующие заявки и составы оплаченных категорий (1 / 4). CRM и публичная страница проверены на широкой и мобильной ширине 390 px. Временное закрытое событие без заявок после проверки удалено; настоящие заявки не изменялись.
