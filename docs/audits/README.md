# HardZone Audit Library

Этот каталог хранит постоянную техническую базу аудитов CRM. Его задача — не заменять профильные документы, а сохранять проверенную карту реализации, связей, критических путей, тестов и известных рисков.

## Как пользоваться

1. Начать с [system-map.md](system-map.md).
2. Открыть аудит нужного раздела.
3. Сверить дату, исходные файлы и раздел `Что изменит выводы аудита`.
4. Проверить актуальные тесты по [test-coverage.md](test-coverage.md).
5. После изменений обновить соответствующий аудит и матрицу покрытия в том же pull request или ветке.

## Статусы

- `verified` — вывод подтверждён кодом и автоматической проверкой.
- `partial` — основные связи подтверждены, но есть непроверенные критические пути.
- `stale` — после аудита менялись ключевые файлы или бизнес-правила.
- `planned` — аудит раздела ещё не проведён.

## Обязательная структура нового аудита

1. Scope и дата.
2. Источники правды и исходные файлы.
3. Сущности и таблицы.
4. API и потребители.
5. Критические пользовательские потоки.
6. Авторизация и границы доступа.
7. Автоматические проверки.
8. Production-наблюдения.
9. Найденные риски и принятые решения.
10. Что изменит выводы аудита.

Не хранить в аудитах токены, cookies, пароли, полные production payload или лишние персональные данные.
