## Отложенный план после финального тестового прогона — 21.09.2026

Владелец сначала полностью прогоняет мероприятие на тестовых результатах. До завершения этого прогона не внедрять окончательную блокировку мероприятия. Текущая защита от обычного удаления комплекса с сохранёнными результатами остаётся. Этот план не является разрешением на очистку данных сейчас.

После прогона, только по отдельному запросу владельца, согласовать и выполнить сброс тестовых результатов и сохранённой сетки с резервной копией, сохранив заявки, оплаты и нужные настройки комплексов. Сброс не реализован как готовая кнопка; его состав и связанные состояния необходимо проверить перед выполнением, включая состояние ручной публикации финальных результатов.

После согласованной очистки, перед реальными соревнованиями, реализовать окончательную фиксацию завершённого мероприятия на сервере: запрет изменения и удаления результатов, повторного открытия комплексов и обхода через изменение расписания. Завершение отдельного комплекса и окончательное завершение всего мероприятия — разные действия.

Также в отложенный план входит удаление пустых настроек оценки вместе с комплексом, если ни одного результата не сохранено. Сохранение хотя бы одного результата уже должно запрещать обычное удаление комплекса; эта защита существует. На момент проверки в базе оставались три пустых черновика удалённых комплексов — они не очищены.

## Таблица ввода — актуальное решение 21.09.2026

Пауза снята владельцем: реализуется таблица «участник → результат, место, баллы» с выбором категории и комплекса, без настроек оценки. ## Подтверждённые правила

- Тип зачёта: время ММ:СС (меньше лучше), повторения или вес (больше лучше), «Время или повторения». В смешанном зачёте завершившие оцениваются по времени и всегда выше не завершивших; последние — по выполненным повторениям. Для каждой команды выбирается вид результата, в JSON сохраняется `{kind,value}`. В одном комплексе один или два самостоятельных зачёта; каждый даёт до 100 баллов.
- Баллы зависят от количества участников категории: актуальные две шкалы указаны выше; минимум 0.
- Одинаковые результаты получают одинаковое место и баллы; последующие места пропускаются (5, 5, 7).
- Общий рейтинг — сумма баллов подтверждённых комплексов. При равенстве сравниваются количества первых, вторых и следующих мест. Если совпало всё, итоговое место общее, с пропуском следующих мест.
- Последний комплекс категории можно отметить финальным. Его заходы и состав команд остаются видны в публичном расписании, а результаты финального комплекса и итоговые места не возвращаются публичным API до отдельной публикации администратором.
- Подтверждённые предварительные результаты остаются доступны в сравнительной таблице. Публикация финала разрешена только после подтверждения финальных комплексов во всех категориях и необратима через обычный интерфейс.

## Сохранение и сетка

Миграция `069_competition_results.sql`: состояние зачётов, записи по id заявок и revision в отдельной таблице. Миграция `071_competition_final_publication.sql` добавляет время явной публикации финала. Заявки и оплаты не изменяются.

Настройки оценки доступны до формирования сетки. Результаты вводятся по актуальной сохранённой сетке; неполный ввод сохраняется черновиком и публично не показывается. Подтверждение требует всех результатов комплекса и обновляет общий рейтинг. Перераспределение включается отдельно для каждого комплекса после первого. Без него состав заходов и дорожек остаётся по исходной регистрации. С ним комплекс ждёт подтверждения всех предыдущих комплексов категории и получает команды по их суммарному рейтингу: лидеры последними. Время, дорожки и резервная вместимость сетки сохраняются.

Повторное формирование сетки учитывает подтверждённые результаты. Изменение состава категории, в которой уже есть результаты, блокирует пересформирование. Удаление/перемещение и смена порядка комплекса с результатами запрещены. Подтверждённый комплекс можно открыть для исправления, пока в зависящем от общего рейтинга следующем блоке нет внесённых результатов; его распределение при этом очищается до повторного подтверждения.

Сохранение проверяет revision результатов, revision расписания и source_hash состава. Пустое поле не равно нулю. Время вводится как продолжительность ММ:СС, а не время суток Excel. DNS/DNF пока не имеют отдельного режима. Блокировка полей объясняется отсутствием сохранённой сетки и/или открытыми настройками; из предупреждения доступна ссылка в расчёт расписания.

## API и защита финала

- GET/PUT `/api/competitions/events/:eventKey/results` — организаторы.
- POST `/api/competitions/events/:eventKey/results/publish-final` — необратимая публикация финального комплекса и итоговых мест после подтверждения финалов всех категорий.
- GET `/api/public/competition/results?event=...` — участники, `Cache-Control: no-store`.
- Публичный API возвращает сохранённое расписание без контактов и внутренних id заявок, а результаты — одной сравнительной таблицей на категорию. До публикации финала сервер исключает финальные зачёты из ответа и считает места только по подтверждённым предварительным комплексам.
- Публичная страница обновляет расписание и таблицу каждые 10 секунд. После ручной публикации в ней одновременно появляются результаты финального комплекса и итоговые места.
