# Результаты соревнований

Раздел «Результаты» внутри мероприятия: ввод по категориям и комплексам, общий рейтинг, ссылка участникам `/competition/results?event=...`. CRM доступна по существующему праву `competitions`. Публичная страница получает только названия команд, результаты, места и баллы — без контактов, оплат и идентификаторов заявок.

## Подтверждённые правила

- Тип зачёта: время ММ:СС (меньше лучше), повторения или вес (больше лучше), «Время или повторения». В смешанном зачёте завершившие оцениваются по времени и всегда выше не завершивших; последние — по выполненным повторениям. Для каждой команды выбирается вид результата, в JSON сохраняется `{kind,value}`. В одном комплексе один или два самостоятельных зачёта; каждый даёт до 100 баллов.
- Баллы за места 1–5: 100, 95, 90, 85, 80. Начиная с 6-го: 77, 74, 71…; после 10-го 62, 59…; минимум 0.
- Одинаковые результаты получают одинаковое место и баллы; последующие места пропускаются (5, 5, 7).
- Общий рейтинг — сумма баллов подтверждённых комплексов. При равенстве сравниваются количества первых, вторых и следующих мест. Если совпало всё, итоговое место общее, с пропуском следующих мест.
- Последний комплекс категории можно отметить финальным. С начала первого финального захода любой категории в сохранённой сетке скрываются все публичные результаты и рейтинг мероприятия. Время — Хабаровск, UTC+10.
- Скрытие фиксируется в БД и не отменяется переносом сетки, правками или завершением финала. Кнопки публикации и автоматического повторного открытия нет. Организаторы сохраняют доступ.

## Сохранение и сетка

Миграция `069_competition_results.sql`: состояние зачётов, записи по id заявок, revision и hidden_at в отдельной таблице. Заявки и оплаты не изменяются.

Настройки оценки доступны до формирования сетки. Результаты вводятся по актуальной сохранённой сетке; неполный ввод сохраняется черновиком и публично не показывается. Подтверждение требует всех результатов комплекса и обновляет общий рейтинг. Следующий комплекс получает команды по общему рейтингу предыдущих подтверждённых комплексов: лидеры последними. Время, дорожки и резервная вместимость сетки сохраняются.

Повторное формирование сетки учитывает подтверждённые результаты. Изменение состава категории, в которой уже есть результаты, блокирует пересформирование. Удаление/перемещение и смена порядка комплекса с результатами запрещены. Подтверждённый комплекс можно открыть для исправления, пока у последующих нет внесённых результатов; посев следующих при этом очищается до повторного подтверждения.

Сохранение проверяет revision результатов, revision расписания и source_hash состава. Пустое поле не равно нулю. Время вводится как продолжительность ММ:СС, а не время суток Excel. DNS/DNF пока не имеют отдельного режима. Блокировка полей объясняется отсутствием сохранённой сетки и/или открытыми настройками; из предупреждения доступна ссылка в расчёт расписания.

## API и защита финала

- GET/PUT `/api/competitions/events/:eventKey/results` — организаторы.
- GET `/api/public/competition/results?event=...` — участники, `Cache-Control: no-store`.
- После начала финала публичный API не возвращает категории, команды, баллы или отдельные результаты. Клиент также убирает уже загруженную таблицу по таймеру начала финала и обновляет данные каждые 10 секунд.
- При изменении расписания сервер проверяет наступление финала по предыдущей сохранённой сетке до применения изменений: перенос не открывает скрытые результаты.

## Пауза и дальнейшее обсуждение — 21.09.2026

Рабочая версия реализована и развёрнута, но пользователь считает процесс ввода слишком запутанным. Следующий этап — обсуждение упрощения, а не автоматическое продолжение разработки. Контекст передачи: `docs/COMPETITION_HANDOFF_2026-09-21.md`.

Предложения перенести тип результата в форму комплекса и разрешить ввод без сохранённой сетки пока **не согласованы**. Текущие ограничения остаются описанием реализации, а не окончательно принятого UX.
