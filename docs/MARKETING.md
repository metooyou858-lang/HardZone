# Маркетинг HardZone

Документ фиксирует реализованный контур CRM-модуля «Маркетинг» и служит входной точкой для дальнейшего развития клиентского приложения.

## Структура раздела

```text
Маркетинг
└── Акции
    └── Кампания
        ├── название и статус
        ├── период действия
        ├── баннер
        ├── публичные правила
        ├── правила наград
        └── участники и факты выдачи наград
```

Первый реализованный сценарий кампании — «Приведи друга».

## Возможности CRM

- Создание и редактирование кампаний без изменения кода.
- Статусы кампании: `draft`, `active`, `archived`.
- Необязательный период действия и баннер JPG/PNG/WebP.
- Публичное описание условий для последующего показа в Telegram/MAX.
- Произвольный набор структурированных наград для пригласившего и приглашённого клиента.
- Типы наград первого этапа: процентная скидка и бесплатные посещения.
- Регистрация пары «кто пригласил → кого пригласили» только по существующим карточкам CRM.
- Отдельные статусы участия и каждой созданной награды.

## Неизменяемый снимок правил

При регистрации участия backend копирует действующие правила кампании в записи `marketing_referral_rewards`. Поэтому изменение кампании влияет только на новых участников и не пересчитывает уже созданные награды.

Статус `issued` фиксирует факт ручной выдачи сотрудником. На текущем этапе он не меняет скидку клиента и не пополняет абонемент автоматически.

## Модель данных

- `marketing_campaigns` — настройки кампаний и правила наград в JSONB.
- `marketing_referrals` — пары клиентов и состояние участия.
- `marketing_referral_rewards` — снимки правил и факты выдачи наград.

В одной кампании приглашённый клиент регистрируется один раз. Самоприглашение запрещено ограничением базы и проверкой API.

## API

Все методы находятся под `/api/marketing`, требуют авторизацию и право `marketing`.

- `GET /api/marketing` — список кампаний.
- `POST /api/marketing` — создание кампании.
- `GET /api/marketing/:id` — кампания, участники и награды.
- `PATCH /api/marketing/:id` — изменение кампании.
- `POST /api/marketing/:id/banner` — загрузка баннера.
- `GET /api/marketing/client-search?q=` — поиск клиентов CRM.
- `POST /api/marketing/:id/referrals` — регистрация пары клиентов.
- `PATCH /api/marketing/referrals/:id/status` — статус участия.
- `PATCH /api/marketing/rewards/:id` — статус награды.

## Доступ

Право `marketing` входит в полный доступ owner/admin. Оно не включено в базовый набор дежурного тренера и может быть выдано или отозвано через существующую систему модулей.

## Связь с клиентским приложением

CRM и backend остаются источником правды. Telegram/MAX не должны хранить отдельные кампании или вычислять награды самостоятельно. Следующий этап клиентского приложения должен получать активную кампанию, баннер, публичные правила и состояние участия через backend API.

## Следующие этапы

1. Добавить клиентские read-only endpoints только для активных кампаний с проверкой периода.
2. Подключить существующий экран акции в Telegram Mini App к данным CRM.
3. Согласовать автоматическое применение скидки в продаже и начисление бесплатного посещения к абонементу.
4. После согласования добавить идемпотентную выдачу награды через продажи/абонементы, сохранив ручной аудит.

Автоматическое применение наград нельзя добавлять отдельно внутри Mini App: оно должно использовать существующие backend-правила продаж, клиентов и абонементов.
